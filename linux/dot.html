DNS over TLS (DoT)

Introdução

O que diabos é TLS e onde raios eu preciso disso na minha conexão? Simples, a requisição feita pra tudo que você conecta na internet é visível, não da pra saber o conteúdo do pacote enviado para consulta de DNS e nem qual página específica você está acessando, mas pra saber que você se conectou no servidor do cornhub da, e isso não só viabiliza a invasão da sua privacidade como também certos ataques... Convencido agora?

É algo tão oculto quanto sei lá, navegar na rede TOR? Não, mas é basicamente fazer dos seus requisitos de DNS como algo invisível para um intermediário com basicamente custo 0.

Para isso você vai precisar dos pacotes stubby, unbound (e expat dependendo da distribuição).

Configurando Unbound

Considerando que o unbound está instalado vamos fazer a configuração inicial com:

sudo unbound-control-setup

Isso preparar os arquivos para a comunicação segura.

Após isso, faça um backup do arquivo /etc/unbound/unbound.conf, e depois deixe ele com o conteúdo abaixo:

server:
  use-syslog: yes
  username: "unbound"
  directory: "/etc/unbound"
  trust-anchor-file: trusted-key.key
  root-hints: "/etc/unbound/root.hints"
  do-not-query-localhost:  no
forward-zone:
  name: "."
    forward-addr: 127.0.0.1@8053
    forward-addr: ::1@8053

Ok, agora vamos baixar o arquivo de de lista de servidores raiz do DNS com o comando:

curl --output /etc/unbound/root.hints https://www.internic.net/domain/named.cache

Esse arquivo precisa ser atualizado com uma certa frequência, para não ter que fazer isso manualmente vamos criar um arquivo de serviço em /etc/systemd/system/roothints.service com o conteúdo:

[Unit]
Description=Update root hints for unbound
After=network.target

[Service]
ExecStart=/usr/bin/curl -o /etc/unbound/root.hints https://www.internic.net/domain/named.cache

E então criar o arquivo /etc/systemd/system/roothints.timer com o conteúdo:

[Unit]
Description=Run root.hints monthly

[Timer]
OnCalendar=monthly
Persistent=true

[Install]
WantedBy=timers.target

E por fim vamos iniciar esse serviço com o comando:

systemctl enable roothints.timer

Configurando Stubby

Considerando que você tem o pacote stubby instalado, basta fazer um backup e depois configurar o /etc/stubby/stubby.yml como no exemplo abaixo:

resolution_type: GETDNS_RESOLUTION_STUB
dns_transport_list:
  - GETDNS_TRANSPORT_TLS
tls_authentication: GETDNS_AUTHENTICATION_REQUIRED
tls_query_padding_blocksize: 256
edns_client_subnet_private: 1
round_robin_upstreams: 1
#idle_timeout: 10000
idle_timeout: 9000
listen_addresses:
  - 127.0.0.1@8053
  - 0::1@8053
upstream_recursive_servers:
  ## Cloudflare IPv4
  ## (NOTE: recommend reducing idle_timeout to 9000 if using Cloudflare)
  - address_data: 1.1.1.1
    tls_auth_name: "cloudflare-dns.com"
  - address_data: 1.0.0.1
    tls_auth_name: "cloudflare-dns.com"
  ## Cloudflare IPv6
  ## (NOTE: recommend reducing idle_timeout to 9000 if using Cloudflare)
  - address_data: 2606:4700:4700::1111
    tls_auth_name: "cloudflare-dns.com"
  - address_data: 2606:4700:4700::1001
    tls_auth_name: "cloudflare-dns.com"

Atenção! Tome bastante cuidado com a sintaxe desse arquivo! A identação aqui possui semântica, e não se utiliza tabulação e sim espaços.

Uma vez configurado inicie os serviços:

sudo systemctl enable stubby unbound

Configurando nameserver

Considerando que você está fazendo uso direto do /etc/resolv.conf (você taambém pode usar o openresolv para gerenciar aqui, embora seja desnecessário), basta deixar de conteúdo as linhas abaixo:

nameserver ::1
nameserver 127.0.0.1
options edns0 trust-ad

Isso vai fazer com que seus requests de DNS sejam resolvidos localmente, depois disso recomendo deixar o arquivo /etc/resolv.conf imutável com o comando:

sudo chattr +i /etc/resolv.conf

E se tudo deu certo você pode testar acessando essa página e verificar se a linha Using DNS over TLS (DoT) retorna Yes.

nftables

Esssa é a configuração mínima recomendada para o /etc/nftables.conf:


table ip filter {

  chain input {
    type filter hook input priority 0; policy drop;
    ct state invalid counter drop comment "IN: drop pacotes invalidos"
    ct state {established, related} counter accept comment "IN: aceita conexoes estabelecidas/relacionadas"
    iif lo accept comment "IN: aceita loopback"
    iif != lo ip daddr 127.0.0.1/8 counter drop comment "IN: bloqueia trafego externo pra loopback"
    ip protocol icmp ct state {established, related} counter accept comment "IN: ICMP established/related"
    counter comment "IN: contagem de dropados"
  }

  chain forward {
    type filter hook forward priority 0; policy drop;
    counter comment "FWD: contagem de dropados"
  }

  chain output {
    type filter hook output priority 0; policy drop;
    oif lo accept comment "OUT: aceita loopback (essencial: unbound -> stubby na porta 8053)"
    ip protocol icmp ct state {new, established, related} counter accept comment "OUT: ICMP"
    tcp dport 853 ct state {new, established} counter accept comment "OUT: DNS-over-TLS TCP (stubby -> Cloudflare)"
    tcp dport 443 ct state {new, established} counter accept comment "OUT: HTTPS (inclui download do root.hints via roothints.timer)"
    counter comment "OUT: contagem de aceitos"
  }
}

table ip6 filter {

  chain input {
    type filter hook input priority 0; policy drop;
    ct state invalid counter drop comment "IN: drop pacotes invalidos"
    ct state {established, related} counter accept comment "IN: aceita conexoes estabelecidas/relacionadas"
    iif lo accept comment "IN: aceita loopback"
    iif != lo ip6 daddr ::1/128 counter drop comment "IN: bloqueia trafego externo pra loopback"
    ip6 nexthdr icmpv6 icmpv6 type { destination-unreachable, packet-too-big, time-exceeded, parameter-problem, echo-request, echo-reply } ct state {established, related} counter accept comment "IN: ICMPv6 established/related"
    ip6 nexthdr icmpv6 icmpv6 type { nd-router-advert, nd-neighbor-solicit, nd-neighbor-advert, nd-redirect } counter accept comment "IN: ICMPv6 NDP essencial"
    counter comment "IN: contagem de dropados"
  }

  chain forward {
    type filter hook forward priority 0; policy drop;
    counter comment "FWD: contagem de dropados"
  }

  chain output {
    type filter hook output priority 0; policy drop;
    oif lo accept comment "OUT: aceita loopback (essencial: unbound -> stubby na porta 8053)"
    ip6 nexthdr icmpv6 icmpv6 type { destination-unreachable, packet-too-big, time-exceeded, parameter-problem, echo-request, echo-reply } ct state {new, established, related} counter accept comment "OUT: ICMPv6 established/related"
    ip6 nexthdr icmpv6 icmpv6 type { nd-router-solicit, nd-neighbor-solicit, nd-neighbor-advert, nd-redirect } counter accept comment "OUT: ICMPv6 NDP essencial"
    tcp dport 853 ct state {new, established} counter accept comment "OUT: DNS-over-TLS TCP (stubby -> Cloudflare IPv6)"
    tcp dport 443 ct state {new, established} counter accept comment "OUT: HTTPS"
    counter comment "OUT: contagem de aceitos"
  }
}
